# ADR-008: Resend API for welcome emails

## Status

Accepted

## Context

ANSP needs to send a welcome message after a benefactor registers and allow an administrator to retry a failed message. The previous SMTP/Nodemailer approach depended on SMTP credentials and network access from the DigitalOcean droplet. The product owner selected Resend.

## Decision

Use the official Resend Node SDK over its HTTPS API. Configure the application with a Resend API key and a sender address on a verified domain. Keep the existing database reservation and send-status behavior: record provider acceptance only after Resend returns a message ID, and never describe that state as proof of inbox delivery.

Do not store the API key in source control, browser code, logs, or the admin UI. Use a sending-only, domain-restricted API key where available. Mock the provider in automated tests; perform a real send only after domain verification and production environment configuration.

## Consequences

- No outbound SMTP port needs to be opened on the droplet; the application makes an HTTPS request to Resend.
- DNS authentication and a verified sender domain are required before production sends can succeed.
- Provider acceptance and the Postgres timestamp update are not atomic, so a process crash between them can still result in a later duplicate attempt.
- Delivery, bounce, and complaint tracking remain outside this feature; the timestamp records API acceptance only.
