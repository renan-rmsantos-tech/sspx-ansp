# ADR-006: Make descriptive public routes canonical with permanent legacy redirects

## Status

Accepted

## Date

2026-08-31

## Context

The current public implementations live at `/form` and `/benfeitor`. The approved public vocabulary requires `/solicitar-bolsa` and `/seja-um-benfeitor`, while old bookmarks and external links must keep working. Duplicate implementations would risk divergent metadata, dynamic behavior, and validation.

## Decision

Make `/solicitar-bolsa` and `/seja-um-benfeitor` the only canonical implementations. Convert `/form` and `/benfeitor` into permanent HTTP 308 redirects to their corresponding canonical routes. Update all owned links and canonical metadata to the new addresses. Preserve dynamic rendering behavior for the scholarship page.

## Alternatives Considered

### Alternative 1: New routes as internal aliases

- **Description**: Keep the old route implementations and rewrite new paths to them.
- **Pros**: Minimal file movement.
- **Cons**: Leaves old technical names canonical and complicates canonical metadata.
- **Why rejected**: The new addresses are the approved public identity.

### Alternative 2: Duplicate both route implementations

- **Description**: Render full page implementations at all four paths.
- **Pros**: Every path works without redirects.
- **Cons**: Creates duplicate content and drift risk.
- **Why rejected**: One canonical implementation is simpler and safer.

## Consequences

### Positive

- Public URLs are descriptive and canonical.
- Existing bookmarks remain functional.
- Each flow has one implementation and one metadata source.

### Negative

- Tests and internal links must be updated to the new paths.
- Clients using old URLs receive a redirect hop.

### Risks

- Moving the scholarship page could drop its dynamic-rendering declaration; verify the canonical page at build time and runtime.
- Relative imports may break during route relocation; prefer shared flow components and validate both canonical paths.

## Implementation Notes

- Use framework-native permanent redirects.
- Add route-level tests for status and destination.
- Search executable sources and operational documentation for owned old links.
