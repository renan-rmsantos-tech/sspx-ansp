# ADR-008: Use one approved seal asset across web pages

## Status

Accepted

## Date

2026-08-31

## Context

The landing, scholarship form, benefactor form, login, and admin top bar currently use several independent SVG implementations. Their geometry differs, and the benefactor version omits seal text. Open Design contains the corrected approved master. The favicon and PDF seal are independent assets and are explicitly outside this release unless they share the same incorrect web source; exploration confirmed that they do not.

## Decision

Publish the approved Open Design master as one static web asset and make the shared web seal component render that asset with caller-controlled size and accessible labeling. Replace every inline or duplicated page-level web seal with the shared component. Leave `app/icon.svg` and `lib/pdf/seal-image.ts` unchanged.

## Alternatives Considered

### Alternative 1: Regenerate favicon and PDF branding too

- **Description**: Replace all seal representations in one release.
- **Pros**: Maximum visual unification.
- **Cons**: Expands review into independent rasterized and document-rendering assets without evidence that they contain the reported defect.
- **Why rejected**: The approved scope covers user-facing web pages.

### Alternative 2: Correct each inline SVG separately

- **Description**: Retain duplicated markup and apply the corrected geometry everywhere.
- **Pros**: Preserves current rendering structure.
- **Cons**: Future changes can drift again, and one current implementation already omits required seal text.
- **Why rejected**: A single approved source eliminates avoidable duplication.

## Consequences

### Positive

- All web pages display the same approved mark.
- Future logo corrections have one web source.
- Page components lose large duplicated SVG blocks.

### Negative

- The web mark becomes dependent on a static asset request.
- Existing component snapshots and layout assumptions may need updates.

### Risks

- An incorrectly copied master could become globally visible; verify the asset against Open Design before adoption.
- Accessible names could be duplicated or lost; let decorative instances be hidden and meaningful instances receive explicit labels.

## Implementation Notes

- Preserve aspect ratio and intrinsic dimensions from the approved SVG.
- The shared component must support decorative and informative usage.
- Validate landing, scholarship, benefactor, login, and admin surfaces at their existing display sizes.
