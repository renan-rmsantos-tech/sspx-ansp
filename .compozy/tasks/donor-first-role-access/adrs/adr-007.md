# ADR-007: Remove the temporary scholarship upload gate

## Status

Accepted

## Date

2026-08-31

## Context

Scholarship uploads are currently disabled by a compile-time constant. The gate affects layout warnings, field visibility, client validation, server validation, and upload-ticket creation. Upload tests already exercise the enabled flow through mocks. The release requires uploads to be permanently available and required.

## Decision

Delete the temporary scholarship-upload flag and disabled-state copy. Make required document fields unconditional in the form and validation schema, and allow the existing server upload-ticket flow for scholarship categories. Preserve current storage isolation, generated paths, file limits, pending-file lifecycle, transaction behavior, and the independent donor receipt flow.

## Alternatives Considered

### Alternative 1: Environment-controlled feature flag

- **Description**: Replace the constant with an environment variable enabled by default.
- **Pros**: Operations could disable uploads without deploying code.
- **Cons**: Retains two product modes and requires every validation layer to stay conditional.
- **Why rejected**: The temporary test mode is no longer a supported product state.

### Alternative 2: Keep the constant set to true

- **Description**: Change the current value and retain all conditional branches.
- **Pros**: Smallest immediate diff.
- **Cons**: Leaves dead provisional behavior, warnings, and test indirection in production code.
- **Why rejected**: The user explicitly requested removal of test flags and alerts.

## Consequences

### Positive

- Client and server share one permanent document requirement.
- Test-phase warnings and dead modes disappear.
- Enabled-path tests can exercise production behavior directly.

### Negative

- Temporarily disabling scholarship uploads will require a deliberate future product change.
- Applicants cannot complete submission when required documents are unavailable.

### Risks

- Removing only some conditional branches could create validation mismatch; inventory every current flag consumer.
- Upload failures become release-critical; keep retry, progress, removal, and error states covered.

## Implementation Notes

- Remove `lib/form/scholarship-uploads.ts` after migrating every consumer.
- Keep the 10 MB limit and application-generated pending paths.
- Update tests that mock the flag to use real enabled behavior.
